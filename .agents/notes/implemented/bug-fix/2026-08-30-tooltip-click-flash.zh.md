# Agent Note: Tooltip 气泡不得在开关按钮点击时闪烁

Status: implemented

[English](2026-08-30-tooltip-click-flash.md) | 中文

## 问题

点击文档面板的折叠按钮会出现可见的闪烁："Collapse document panel"气泡在 mousedown 时弹出、松手约 10 ms 后消失，随后——光标仍停在原地——另一个开关的气泡约半秒后又在其下方弹出。带埋点的 e2e 运行（帧截图 + 逐事件时间戳）表明两个现象都是共享 `Tooltip` 原语触发模型的缺陷，而不是布局问题：

1. **焦点闪烁。** `Tooltip` 在任何 focus 时都立即显示气泡。mousedown 会给按钮聚焦，所以每次点击带 tooltip 的控件都会在整个按压期间闪现自己的标签，随后在按钮失焦（通过 `inert` 或 `hidden`）时又将其隐藏。
2. **合成 hover 闪烁。** 面板切换时，另一个开关会出现在静止光标之下的同一坐标处。Chromium 在该布局变化后重新执行命中测试，向新的最顶层元素派发合成的 `mouseover`/`mouseenter`——完全没有指针移动（`mouseover` 落在 mouseup 后约 10 ms，且此前没有 `mousemove`）。这启动了 500 ms 的 hover 计时器，于是点击后半秒后气泡在零指针意图的情况下出现——两个方向都有：收起之后（重开按钮上）和重新打开之后（折叠按钮上）。

## 决策

`Tooltip` 的触发模型现在与用户意图一致：

- **hover 由进入锚点的指针移动启动，而不是仅凭 `mouseenter`。** 锚点内的第一个 `mousemove` 启动延迟计时器（每次停留只启动一次；后续移动不重置它）。真实 hover 的跨越移动与 enter 在同一事件批次中指向该锚点，因此同一帧内即完成启动；而出现在静止光标之下的元素只会收到没有移动的合成 enter，在指针真正移动之前永远不会显示。
- **按压会取消任何待处理的 hover 显示。** 真实的手在点击前总会产生一次真实的移动，因此用户按下时延迟计时器往往已经启动——若不取消，它会在按压期间或松手后立刻触发，恰好在用户操作时弹出标签（文档面板重开方向残留的闪烁）。锚点上的 `pointerdown` 会丢弃待处理显示并重置启动状态；下一次真实移动重新启动。已经因完整 hover 而可见的气泡保持不动：指针仍停在锚点上。
- **按压来源的聚焦从不显示；其余聚焦立即显示。** Chromium 对所有 focus 事件都报告 `detail === 0`——包括鼠标点击（已实测验证；规范中的点击计数语义并未实现），因此 `detail` 无法区分键盘聚焦与鼠标聚焦。改为由锚点记录自己的 `pointerdown` 时间戳：落在其后 300 ms 内的聚焦视为按压自身的聚焦并予以抑制；更晚的聚焦（键盘 Tab、程序化）立即显示，由 spec 固定。对已聚焦按钮的再次点击根本不会触发新的 focus 事件，因此没有需要抑制的对象。

文档面板的两个开关都保留 hover tooltip——在"移动才启动"的规则下，两者都不可能在没有指针意图的情况下弹出气泡。

## 后果

- 所有 Tooltip 使用方（约 50 处调用）都消除了点击时亚秒级的标签闪烁；复制按钮、rail 控件和面板开关都不再在按压期间闪现自己的标签。
- 任何 tooltip 都不会在静止光标之下弹出，两个切换方向皆如此；气泡现在要求指针在其锚点上发生真实的移动。
- 文档面板的折叠/重开配对对真实 hover（enter + move 在同一帧内启动）和键盘聚焦的行为与之前完全一致。

## 相关决策

locale key `docPanel.panel.expand` / `docPanel.panel.collapse` 仍通过两个按钮的 tooltip 和 `aria-label` 使用。侧边栏浮动展开按钮基于它自己的决定（位于窗口 chrome 之上）继续保持无 tooltip。

## 曾考虑的替代方案

- **用 `nativeEvent.detail` 门控聚焦**（键盘 = 0，鼠标 >= 1）。规范中的点击计数语义看似正好合适，但 Chromium 对鼠标点击的 focus 事件在所有探测配置下都报告 `detail === 0`——该修复在 jsdom 中通过、却在真实浏览器中失效。记录在此，以免重蹈这个死胡同。
- **移除文档面板开关的 tooltip**（即侧边栏浮动开关的模式）。无需改动共享基础设施即可修复观察到的闪烁，但它让该缺陷类别对所有其他"可能出现在静止光标之下"的 tooltip 锚点元素保持存活，而且失去了两个开关现有的 hover 提示。
- **用"移动新鲜度"时间戳门控启动**（一个"陈旧移动"阈值）。与"移动才启动"结果相同，但引入了魔法常量，并且在反方向上会失败：指针刚进入锚点就快速停下时，粗糙的阈值会把它判定为陈旧。
- **延迟到轨道动画结束后再显示重开按钮。** 按钮仍会出现在静止光标之下——同样的合成 `mouseenter`、同样的延迟气泡。
- **在过渡期间切换 tooltip 的 `disabled`。** 为一个纯展示层的产物引入瞬态组件状态标志，而且焦点闪烁仍然存在。
